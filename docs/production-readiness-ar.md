# بوابة الجاهزية للإطلاق

## الحالة التنفيذية الحالية

أضيفت في هذا الفرع تحسينات تشغيلية وأمنية واختبارات، لكن **لم يُنفذ نشر خارجي على Vercel، ولم تُضف أسرار حسابات Vercel/AWS، ولم تُجر جلسة UAT أو توقيعات الأنشطة والمالية والقانون**. وجود إعدادات وأتمتة في المستودع لا يساوي نجاح تشغيلها.

آخر تحقق محلي في هذه البيئة: **45 اختبارًا ناجحًا، و5 اختبارات PostgreSQL متخطاة لعدم وجود PostgreSQL/Docker هنا، وتحذير اعتماديات واحد**؛ شغّلت الاختبارات على Python 3.11 وSQLite. اجتاز `compileall` كذلك. على GitHub Actions/Python 3.12، طُبقت migrations `0001`–`0003` ونجحت اختبارات SQLite، لكن خطوة تكامل PostgreSQL أخفقت في أول تشغيل للـcommit `212ac53`؛ أضيف إخراج تشخيصي للـrerun، ولا توجد نتيجة نجاح PostgreSQL أو استعادة بعد. كما فشل فحص نشر Vercel Preview التلقائي لذلك الـcommit؛ سبب فشل Vercel غير ظاهر في حالة GitHub ولا أعدّه نشرًا ناجحًا. لم تُنشأ بيئة GitHub المسماة `staging` بعد.

## ما أُضيف برمجيًا

- Migration `0003_mfa_sessions.sql` لتخزين حالة MFA، أسرار TOTP المشفرة، عداد منع إعادة استخدام الرمز، وحالة تحقق الجلسة. يتطلب الإنتاج `MFA_ENCRYPTION_KEY` مستقلًا صالحًا لـFernet.
- MFA باستخدام TOTP للحسابات الإدارية/الحساسة في الإنتاج (`super_admin`, `group_manager`, `business_manager`, `contract_manager`, `accountant`). يجبر الدخول لأول مرة على التسجيل؛ أسرار TOTP لا تحفظ نصًا صريحًا؛ يُرفض الرمز المعاد استخدامه. إعادة تعيين كلمة المرور بواسطة المدير تمسح MFA وتفرض التسجيل مجددًا.
- قفل صف الطلب والصنف عند تنفيذ طلبات Sawa Food لمنع تنفيذ الطلب مرتين أو تجاوز المخزون بالتزامن. تبقى قيود PostgreSQL الزمنية للحجوزات ضمن migration 0001.
- فحص أعمدة المخطط المطلوبة عند بدء الإنتاج بدل الاكتفاء بوجود أسماء الجداول.
- قبول `S3` الخاص وماسح HTTPS موثوق فقط في الإنتاج. الرفع يفشل مغلقًا عند رفض الملف أو غياب الماسح؛ تمت إضافة حالة EICAR إلى اختبارات mock وسكربت اختبار خارجي لا يكتب إلى S3.
- خدمة scanner تجريبية محدودة تستخدم ClamAV، مع منفذ ClamAV داخلي وواجهة `/scan` مصادق عليها. يجب وضعها خلف HTTPS وتحديث قاعدة الفيروسات وتشغيلها على مضيف خاص.
- سجلات JSON لطلبات HTTP مع `X-Request-ID` دون جسم الطلب أو IP، وسكربت فحص `/health` و`/ready`، وWorkflow دوري اختياري للتنبيه.
- إعداد WAF يدوي مطلوب على Vercel؛ حدّث إعداد Nginx البديل لتحديد المعدل والاتصالات وفرض TLS.
- قالب CloudFormation للـbucket الخاص، وتفعيل versioning والتشفير ومنع الوصول العام، وسياسة IAM محدودة.
- سكربت backup واستعادة آمنة إلى قاعدة منفصلة، وWorkflow CI لعمل dump واستعادته والتحقق من الجداول.
- نموذج UAT واعتمادات منفصل في `docs/uat-acceptance-ar.md`؛ جميع موافقاته تبدأ `معلق` ولا توجد توقيعات مدعاة.

## بوابات لا تزال مطلوبة قبل إدخال بيانات حقيقية

1. **تشغيل CI:** شغّل `.github/workflows/tests.yml` واحتفظ بنتيجة ناجحة لاختبارات PostgreSQL والمigrations والتزامن والصلاحيات ونسخ/استعادة CI.
2. **نشر staging الحقيقي:** أنشئ Vercel Preview مستقلًا واربط نطاق staging الثابت، ثم أضف أسرار GitHub/Vercel المذكورة في `docs/staging-hardening-ar.md`. شغّل `.github/workflows/staging-deploy.yml` وتحقق من `/health` و`/ready`.
3. **الخدمات الخارجية:** أنشئ قاعدة PostgreSQL مُدارة مستقلة، وطبّق migrations `0001` ثم `0002` ثم `0003` على قاعدة staging بعد مراجعتها؛ أنشئ bucket staging بالقالب؛ شغّل ClamAV على مضيف خاص، مع TLS وtoken، ثم نفذ `scripts/verify_external_scanner.py`. يجب اختبار EICAR على خدمة ClamAV فعلية وتأكيد عدم كتابة أي object.
4. **الحماية والمراقبة:** فعّل قواعد Vercel Firewall/WAF وإشعارات المراقبة، وتأكد أن alert يصل بعد فشل `/ready`. ملفات المشروع لا تستطيع إنشاء قواعد WAF في حساب Vercel. في staging استخدم `.github/workflows/staging-monitor.yml` بعد إضافة `STAGING_BASE_URL` و`ALERT_WEBHOOK_URL`.
5. **الاستعادة:** نفذ `scripts/backup_postgres.sh` ثم `scripts/verify_postgres_restore.sh` في بيئة staging على قاعدة فارغة منفصلة، وسجل RPO/RTO وتحقق من بيانات العينة وS3 Versioning. لا تختبر الاستعادة على production.
6. **المراجعة الأمنية:** اختبر MFA مع تطبيق authenticator، دورة استعادة حساب المدير، صلاحيات كل دور وعزل الأنشطة، واختبار اختراق مستقل. لا تعتبر مراجعة الوثائق أو اختبارات الوحدة بديلًا عن ذلك.
7. **اعتمادات الأعمال:** أكمل حالات UAT ووقع مسؤولو كل نشاط. يجب اعتماد المحاسب للتقريب والعملات والرديات/التسويات، والمستشار القانوني للعقود والضرائب والخصوصية في الدول المعنية. ما زالت وظائف الأقساط والمطابقة البنكية وFX والتوقيع الإلكتروني المتقدم خارج نطاق الـMVP.
8. **قرار Go/No-Go:** لا يُدخل بيانات حقيقية ولا تعتمد المنصة كسجل مالي/قانوني رسمي حتى تكتمل جميع الخطوات وتُحفظ نتائجها وموافقاتها.

## إجراءات النشر والنسخ والاستعادة

اتبع `docs/staging-hardening-ar.md` لإنشاء staging والخدمات وإعداد WAF. يستخدم `scripts/backup_postgres.sh` متغيرات libpq (`PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE` و`.pgpass` أو `PGPASSWORD`) بدل وضع connection URI يحوي كلمة مرور في سطر الأوامر. ينتج السكربت archive غير مشفر على مستوى الملف؛ احفظه على volume مشفر وشفره قبل نقله خارجيًا. استخدم `scripts/verify_postgres_restore.sh` بعد تعيين `RESTORE_TARGET_DATABASE` و`RESTORE_TARGET_CONFIRMATION` إلى اسم قاعدة مؤقتة فارغة؛ يرفض السكربت العمل مع `APP_ENV=production` أو استهداف قاعدة المصدر.

لـDocker البديل، ابدأ بعد إكمال جميع متغيرات `.env.example` (MFA وS3 والماسح ضمنها) وتطبيق migrations. لا يرقّي Docker initdb volume موجودًا تلقائيًا؛ لا تحذف volume الإنتاج لإجبار التهيئة. للنشر على Vercel اتبع `docs/vercel-deployment-ar.md`.
