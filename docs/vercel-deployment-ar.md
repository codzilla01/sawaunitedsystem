# نشر SAWA UNITED على Vercel — المكتب الرئيسي في مصر

## ما تم تجهيزه

- نقطة دخول ASGI في `api/index.py` ومسار موحد في `vercel.json` يشغل الواجهة وAPI على نفس الأصل.
- Python 3.12 واعتماديات مثبتة عبر `requirements.txt` ← `requirements.lock`.
- PostgreSQL خارجي؛ تعطيل pool المحلي على Vercel لتجنب تضاعف الاتصالات. استخدم عنوان اتصال pooled من مزود قاعدة البيانات مع TLS.
- مستندات خاصة عبر S3، وليست ملفات محلية أو روابط عامة. التنزيل يمر عبر جلسة المستخدم وفحص نطاق نشاطه.
- فحص المستندات قبل التخزين، والرفض عند تعطل الفحص أو غياب حكم صريح بسلامة الملف.
- صفحة مستندات عربية لاختيار العميل أو العقد والنشاط ورفع الملف وتنزيله.
- حد رفع 3 MiB على Vercel لإبقاء multipart والرد ضمن حدود الطلب/الرد المعتادة للوظائف. الملفات الأكبر تحتاج مسار رفع مباشر خاص مع حجر وفحص غير متزامن، وهو غير منفذ هنا.
- 10 محاولات دخول لكل حساب في نافذة 15 دقيقة بعملية PostgreSQL ذرية مشتركة بين الوظائف. هذا لا يغني عن حماية Vercel Firewall/WAF ضد تبديل الحسابات والهجمات الموزعة.
- MFA باستخدام TOTP للحسابات الحساسة في الإنتاج، مع تشفير الأسرار بمفتاح Fernet مستقل ومنع إعادة استخدام الرمز.
- Workflow نشر staging يدوي وفحص دوري لـ`/health` و`/ready` بعد ربط الأسرار والنطاق، إضافة إلى اختبارات PostgreSQL والنسخ/الاستعادة في CI.
- لا يتم إنشاء مدير أو تشغيل migrations في البناء أو عند كل cold start.

## حالة التفعيل

التعديلات البرمجية موجودة، لكن الموقع **لم يُنشر ولم يُختبر على حساب Vercel بعد**، ولم تُضف أسرار staging أو حساب AWS إلى GitHub/Vercel من هذا المستودع. أضيف Workflow نشر يدوي، لكنه يتوقف حتى تهيئة البيئة. الاختبارات المحلية لا تستخدم PostgreSQL الفعلي. يلزم ربط الحسابات وتوفير الخدمات أدناه؛ لا يمكن تشغيل PostgreSQL أو Docker Compose أو ClamAV كخدمات دائمة داخل وظيفة Vercel.

## الخدمات المطلوبة

1. مشروع Vercel مرتبط بهذا المستودع، مع نطاق HTTPS ثابت.
2. PostgreSQL مُدار، مع نسخ تلقائي وPITR وخطة استعادة مجربة.
3. bucket AWS S3 خاص مع Block Public Access والتشفير وVersioning. يوفّر `infra/aws/private-documents-bucket.yml` قالب CloudFormation مع سياسة IAM محدودة لـ`GetObject` و`PutObject` و`DeleteObject`. لا تمنح وصولًا عامًا أو صلاحيات إدارة الحساب.
4. خدمة فحص خاصة عبر HTTPS؛ يتضمن `deploy/scanner/` adapter لـClamAV يعمل على مضيف منفصل ولا يعرّض منفذ ClamAV للعامة. البروتوكول المطلوب: `POST` لمحتوى الملف الخام، `Authorization: Bearer TOKEN`، والرد `HTTP 200` و`{"clean": true}` **فقط بعد إكمال الفحص الحقيقي**. لا تستخدم خدمة تعيد هذا الرد دون فحص، ولا ترسل وثائق حقيقية إلى ماسح عام. يلزم اختبارها بملف EICAR في بيئة تجريبية والتحقق من رفضه.
5. اختَر مناطق الخدمات وفق متطلبات المؤسسة ومراجعة حماية البيانات في مصر؛ لا يفترض المشروع أن بياناتك تبقى داخل مصر لمجرد أن المكتب فيها.

## إعداد Vercel

استورد المستودع، واستخدم الجذر الحالي للمشروع. لا تضع أمر بناء frontend أو output directory. يستخدم ملف Vercel مدخل Python؛ لا تستخدم `npm start` كأمر بناء.

أضف القيم التالية في بيئة **Production**، ثم أنشئ قيمًا وخدمات مستقلة داخل **Preview** للـstaging. لا تشارك أسرار الإنتاج مع Preview:

| المتغير | المطلوب |
|---|---|
| `APP_ENV` | `production` |
| `PUBLIC_ORIGIN` | `https://your-domain` بدون شرطة أخيرة |
| `COOKIE_SECURE` | `true` |
| `SECRET_KEY` | سر عشوائي فريد، 48 حرفًا على الأقل |
| `MFA_ENCRYPTION_KEY` | مفتاح Fernet مستقل لتشفير أسرار TOTP؛ أنشئه بـ`Fernet.generate_key()` |
| `DATABASE_URL` | `postgresql+psycopg://...?...sslmode=require`؛ راعِ فواصل query الصحيحة وURL encoding لكلمة المرور |
| `S3_BUCKET`, `S3_REGION` | bucket خاص ومنطقته |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | مفتاح محدود الصلاحيات |
| `S3_ENDPOINT_URL` | اختياري، عنوان HTTPS لتخزين متوافق يدعم SSE-S3 |
| `DOCUMENT_SCANNER_URL`, `DOCUMENT_SCANNER_TOKEN` | ماسح HTTPS خاص موثوق ومتوافق مع البروتوكول أعلاه |

يفضل AWS S3 أولًا؛ لم يُجرّب مزود متوافق آخر. يجب أن يدعم `ServerSideEncryption=AES256`. لا تضع أسرار الإنتاج في Preview أو متغيرات عامة للواجهة. ضع قاعدة بيانات وbucket وماسح منفصلين لـPreview، أو عطّل نشر Preview. Vercel يضبط متغير `VERCEL` تلقائيًا.

## التهيئة مرة واحدة (لا توجد بيانات قديمة)

من جهاز إداري آمن، طبق ملفات SQL **بالترتيب على قاعدة جديدة فارغة** بعد المراجعة. الأدوات الإدارية قد تتطلب عنوان اتصال مباشر بدل pooled. `psql` يستخدم رابط `postgresql://`، أما التطبيق فيستخدم `postgresql+psycopg://`.

```bash
psql "$ADMIN_DATABASE_URL" -v ON_ERROR_STOP=1 --single-transaction -f migrations/0001_initial_postgresql.sql
psql "$ADMIN_DATABASE_URL" -v ON_ERROR_STOP=1 --single-transaction -f migrations/0002_login_budgets.sql
psql "$ADMIN_DATABASE_URL" -v ON_ERROR_STOP=1 --single-transaction -f migrations/0003_mfa_sessions.sql
```

صدّر إعدادات الإنتاج محليًا بطريقة آمنة، مع `BOOTSTRAP_ADMIN_EMAIL` و`BOOTSTRAP_ADMIN_PASSWORD` فريدة لا تقل عن 16 حرفًا، ثم:

```bash
python -m pip install -r requirements.txt
python -m scripts.initialize_production
```

هذا ينشئ البيانات المرجعية والمدير، ولا ينفذ ملفات SQL بدلًا عنك. لا يلزم حفظ كلمة مرور bootstrap في Vercel بعد التهيئة. لا تعِد التهيئة ببريد مختلف إلا إذا أردت إنشاء مدير آخر عمدًا.

## اختبار ما قبل تفعيل المستخدمين

- نجاح `/health` و`/ready`، ثم الدخول والخروج من النطاق الصحيح.
- إنشاء حساب محدود لكل موظف وعدم مشاركة حساب المدير.
- رفع PDF تجريبي صغير والتحقق من تنزيله بعد cold start وإعادة نشر Vercel.
- رفض التنزيل بلا جلسة، ورفض مستخدم نشاط آخر، ورفض ملف كبير أو نوع مزيف.
- شغّل `python scripts/verify_external_scanner.py` على scanner staging فعلي؛ ينبغي قبول ملف سليم ورفض EICAR دون أي كتابة إلى S3. عطّل الماسح مؤقتًا وتأكد أن حفظ المستند يفشل مغلقًا.
- التأكد من أن bucket غير قابل للقراءة العامة وعدم وجود مفاتيح في المستودع أو ردود API.
- تجربة حد الدخول على حساب تجريبي لا حساب المدير.
- اختبار `scripts/backup_postgres.sh` ثم استعادة النسخة إلى قاعدة staging فارغة عبر `scripts/verify_postgres_restore.sh`، والتحقق من S3 versioning وتوثيق RPO/RTO.
- إكمال حالات `docs/uat-acceptance-ar.md` وتوقيع مسؤولي الأنشطة والمالية والقانون وحماية البيانات؛ لا تستبدل الموافقات البشرية بنتيجة الاختبارات.
- ضبط Vercel Firewall/WAF ومراقبة GitHub staging workflow، واختبار التنبيه عند تعطل `/ready`.
- مراجعة القيود المالية والامتثال؛ تقوية الاستضافة لا تكمل وظائف الأقساط والتسويات وFX غير المنفذة.

## قيود معروفة

لم تُختبر الخدمات الخارجية أو النشر الفعلي في هذه الجلسة. الاختبارات المحلية تستخدم mocks للتخزين والماسح وSQLite للمسارات. Workflow CI يطبّق PostgreSQL migrations ويشغّل اختبارات تزامن/نطاق/استعادة، لكن يجب تشغيله والتحقق من نتيجته قبل الاعتماد. عند فشل حفظ سجل المستند تُجرّب إزالة الكائن، لكن الانقطاع المفاجئ قد يترك كائنًا يتيمًا؛ راقب المصالحة مع سجلات المستندات وضع سياسة حذف مدروسة لا تحذف ملفات مرتبطة. عدد المستخدمين الفعلي والحمل المتوقع لم يحددا بعد، ويلزم قياس الحمل قبل توسيع الاستخدام.
