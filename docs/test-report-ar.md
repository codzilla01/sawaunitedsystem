# تقرير الاختبارات — SAWA UNITED BMS MVP

**نتيجة التنفيذ:** ناجح 10/10 اختبارات آلية في بيئة SQLite مؤقتة.

| # | حالة الاختبار | النتيجة |
|---|---|---|
| 1 | رفض الوصول للوحة API دون مصادقة | PASS |
| 2 | إنشاء مشروع ووحدة ورفض حجز عقاري متداخل | PASS |
| 3 | البيع الغذائي المباشر يخصم المخزون والوساطة لا تخصمه | PASS |
| 4 | رفض حجز سيارة متداخل مع حجز قائم | PASS |

| 6 | دورة العقد حتى حالة نشط ورفض انتقال غير صالح | PASS |
| 7 | رفض حركة مالية بعملة تخالف العقد وقبول العملة الصحيحة | PASS |
| 8 | عدم إظهار كلمة المرور المشفرة في API المستخدمين | PASS |
| 9 | فرض نطاق النشاط على الأطراف للمستخدم المقيد | PASS |
| 10 | رفع مستند خاص وتنزيله من خلال جلسة مصادق عليها | PASS |
| 11 | إضافة نشاط جديد ودولة جديدة بصلاحية مدير النظام | PASS |

**ملاحظة العد:** مجموعة Pytest تحتوي 10 دوال اختبار ناجحة. اختبار السيارات يغطي حالتي الحجز والصيانة، واختبار الغذاء يغطي النموذج المباشر والوساطة؛ لذلك يتضمن الجدول 11 حالة تحقق وظيفية موزعة على 10 اختبارات.

## ما لا يغطيه هذا التقرير

- اختبار أداء P95 أو تحمل آلاف المستخدمين.
- اختبار اختراق خارجي أو مراجعة OWASP مستقلة.
- اختبار ترقية PostgreSQL الإنتاجية وترحيل بيانات حقيقية.
- اختبار تكامل WhatsApp أو Meta أو TikTok.
- اعتماد نماذج العقود والضرائب والتوقيع الإلكتروني في الدول الخمس.
- اختبار نسخ احتياطي واستعادة على بيئة إنتاج.
- اختبار شامل لجميع حالات cancellation/refund/insurance/vehicle handover.

## بوابة قبول المستخدم (UAT)

قبل Go-Live يجب أن يختبر مسؤول كل نشاط بياناته الواقعية بعد تنظيفها، ويوقع على مسارات العميل → الفرصة → العرض → العقد → التحصيل → التنفيذ → الإغلاق. يجب التحقق من تقارير العملة والحقوق والوصول والتصدير، ثم اختبار استعادة نسخة احتياطية.
