# SAWA UNITED Business Management System

نسخة MVP قابلة للتشغيل لمنصة الإدارة الداخلية الموحدة لمجموعة SAWA UNITED. تضم نواة CRM والعقود والمالية، ووحدات العقارات وSawa Food وMashary Cars.

## تقوية النشر الإنتاجي

أضيفت إعدادات نشر HTTPS مستقلة في `compose.production.yml`، وحماية CSRF، وفحص إعدادات الإنتاج، وملف اعتماديات مثبت، واختبارات أمان. **هذه ليست موافقة على إدخال بيانات حقيقية بعد**: راجع [بوابة الإطلاق الإنتاجي](docs/production-readiness-ar.md) للشروط المتبقية وخطوات النشر والنسخ والاستعادة. أضيف مسار تخزين S3 خاص مع فحص إلزامي للمستندات قبل الحفظ في الإنتاج. للنشر على Vercel راجع [دليل Vercel](docs/vercel-deployment-ar.md)؛ يلزم تهيئة الخدمات الخارجية قبل التفعيل.

## حالة التسليم

- قاعدة بيانات علائقية عبر SQLAlchemy 2.
- SQLite للتشغيل المحلي والتجارب، ودعم PostgreSQL عبر `DATABASE_URL`.
- واجهة ويب عربية RTL متجاوبة.
- REST API موثق تلقائيًا عبر OpenAPI / Swagger.
- جلسات دخول عبر Cookie من نوع HttpOnly مع تخزين بصمة الجلسة في قاعدة البيانات.
- عزل صلاحيات حسب الدور والنشاط، وربط ملف الطرف بالأنشطة المصرح بها.
- ملفات خاصة خارج المجلد العام، مع التحقق من الامتداد/النوع والتوقيع والحجم.
- MFA للحسابات الإدارية في الإنتاج، وسجلات طلبات JSON مع معرف تتبع.
- اختبارات محلية على SQLite؛ راجع النتيجة الحالية وقيود PostgreSQL في `docs/test-report-ar.md`.

> هذه نسخة MVP تشغيلية وليست بعدُ نظامًا إنتاجيًا مكتمل الاعتماد المالي/القانوني. راجع قسم «قبل الإنتاج» قبل استخدامها مع بيانات حقيقية.

## التشغيل المحلي — Windows PowerShell

```powershell
cd sawa_united_system
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

ضع قيمة سرية قوية في `SECRET_KEY` داخل `.env`، وغيّر `BOOTSTRAP_ADMIN_PASSWORD` إلى كلمة مرور فريدة لا تقل عن 12 حرفًا. ثم:

```powershell
uvicorn app.main:app --reload
```

افتح `http://127.0.0.1:8000`.

بيانات الدخول الأولية تُقرأ من `.env`:
- `BOOTSTRAP_ADMIN_EMAIL`
- `BOOTSTRAP_ADMIN_PASSWORD`

إذا كانت قاعدة البيانات قد أُنشئت سابقًا، فتغيير قيمة Bootstrap في `.env` لا يغيّر كلمة مرور المستخدم الموجود. استخدم مسار إعادة تعيين كلمة المرور أو حدّثها بإجراء إداري آمن.

## التشغيل باستخدام npm (اختياري)

ملف `package.json` يوفر اختصارات لتشغيل مشروع Python الحالي؛ لا يضيف خادم Node.js أو خطوة بناء للواجهة. تبقى اعتماديات التطبيق في `requirements.txt`، ولا يكفي `npm install` لتثبيتها.

بعد تثبيت Python وتفعيل البيئة الافتراضية بحيث يكون الأمر `python` متاحًا، نفّذ:

```bash
npm run setup
npm run dev
```

- `npm run setup`: تثبيت اعتماديات Python في البيئة النشطة.
- `npm run dev`: تشغيل FastAPI مع إعادة التحميل على المنفذ 8000.
- `npm start`: تشغيل التطبيق دون إعادة التحميل (ليس بديلًا عن إعدادات نشر الإنتاج).
- `npm test`: تشغيل اختبارات Python.

تُستخدم إعدادات البيئة الموضحة أعلاه أيضًا مع هذه الأوامر. يستمع الخادم على `0.0.0.0` ليدعم الحاويات والمعاينة، ويمكن فتحه محليًا عبر `http://127.0.0.1:8000`.

## التشغيل عبر Docker

```bash

```

## إعدادات البيئة

| المتغير | الوصف |
|---|---|
| `APP_ENV` | development أو production |
| `SECRET_KEY` | سر التطبيق المستخدم في بصمة الجلسات؛ إلزامي وقوي في الإنتاج |
| `MFA_ENCRYPTION_KEY` | مفتاح Fernet مستقل لتشفير أسرار TOTP؛ إلزامي في الإنتاج |
| `DATABASE_URL` | SQLite محليًا أو PostgreSQL URL في الإنتاج |
| `S3_BUCKET`, `S3_REGION` | bucket خاص للمستندات في الإنتاج |
| `DOCUMENT_SCANNER_URL`, `DOCUMENT_SCANNER_TOKEN` | ماسح HTTPS فعلي؛ فشل الماسح يمنع الرفع |
| `SESSION_TTL_HOURS` | مدة الجلسة بالساعات |
| `COOKIE_SECURE` | يجب أن تكون true خلف HTTPS في الإنتاج |
| `BOOTSTRAP_ADMIN_EMAIL` | البريد الأولي للمدير |
| `BOOTSTRAP_ADMIN_PASSWORD` | كلمة مرور المدير عند إنشاء الحساب أول مرة |
| `UPLOAD_ROOT` | مجلد تخزين الملفات الخاصة خارج static |

## قبل الإنتاج — بوابة إلزامية

1. تشغيل Workflow CI فعليًا والتحقق من PostgreSQL migrations واختبارات التزامن والصلاحيات وbackup/restore؛ وجود workflow وحده ليس نتيجة ناجحة.
2. نشر Vercel Preview على staging منفصل، وتهيئة PostgreSQL وS3 خاص وClamAV فعلي واختبار EICAR؛ لم تُنشأ خدمات الحسابات من داخل المستودع.
3. تفعيل MFA للحسابات الحساسة، وقواعد WAF في لوحة Vercel ومراقبة التنبيهات بعد نشر staging.
4. تنفيذ استعادة فعلية لقاعدة staging منفصلة، واعتماد RPO/RTO وخطة استعادة S3.
5. مراجعة أمنية واختبار اختراق مستقل بعد اختبار جميع الأدوار ونطاقات الأنشطة.
6. اعتماد المحاسب للقيم والعملات والتقريب والرديات والتسويات، واعتماد المستشار القانوني للعقود والضرائب والخصوصية لكل سوق.
7. إكمال UAT وتوقيع مسؤولي كل نشاط في `docs/uat-acceptance-ar.md`؛ جميع التواقيع ما زالت مطلوبة.
8. الوظائف المالية المتقدمة والتوقيع الإلكتروني والتكاملات الاجتماعية ليست مكتملة؛ لا تستخدم نسخة MVP كسجل مالي أو قانوني رسمي قبل اعتمادها.

راجع [بوابة الإطلاق](docs/production-readiness-ar.md) و[إعداد staging](docs/staging-hardening-ar.md) قبل إدخال أي بيانات حقيقية.

النسخة الحالية تثبت البنية الأساسية ومسارات تشغيل رئيسية لكل نشاط، لكنها لا تتضمن بعدُ جميع الوظائف المحددة في PRD مثل إدارة الصيانة المتقدمة ومحاضر الاستلام/التسليم التفصيلية، إدارة مخزون دفعات الصلاحية والمستودعات، جداول الأقساط والتسويات المتقدمة، التوقيع الإلكتروني، تكاملات القنوات، التقارير الربحية المتقدمة أو بوابة العميل. هذه بنود تنفيذ تالية ضمن نفس المنتج، وليست وظائف مكتملة في التسليم الحالي.
